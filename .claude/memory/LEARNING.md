# Learned concepts (her cheat sheet)
- Generic `CustomActionResult<T>` = TypeScript `ApiResponse<T>`; `<T>` is filled in at the use site (`CustomActionResult<List<Books>>`).
- `IActionResult` + `Ok(x)` = controller returns "HTTP 200 with JSON body x"; like returning a value from an Angular service, but the framework turns it into the response.
- Object initializer `new X { A = 1 }` = TypeScript object literal `{ a: 1 }` typed as class X.
- `ConfigureApiBehaviorOptions` in `Program.cs` = a global setting for `[ApiController]` behaviour; here it makes validation errors (400) use our envelope — like an Angular `HttpInterceptor` shaping errors in one place.
- `app.UseExceptionHandler` = global error handler middleware, like Angular `ErrorHandler` — any unhandled exception ends up here and becomes the 500 envelope.
- `?` after a type (`string?`, `Books?`) = may be `null`, like `string | null` in TypeScript (`Nullable` is enabled in the csproj).
- NuGet package (`<PackageReference>` in the `.csproj`) = npm dependency in `package.json`; `dotnet add package X` = `npm install X`. `Dapper` runs SQL/stored procedures and maps rows to classes; `Microsoft.Data.SqlClient` is the driver that talks to SQL Server.
- `ConnectionStrings:Bookshop` in `appsettings.json` = a value in Angular `environment.ts`; `appsettings.Development.json` overrides it in Development (like `environment.development.ts`). Read later with `configuration.GetConnectionString("Bookshop")`.
- Collation = the rules a database uses to compare/sort text. `CI` = case-insensitive, `AI` = accent-insensitive; `Persian_100` = Persian sorting rules. Set once on the database (`CREATE DATABASE ... COLLATE ...`).
- Middleware order in `Program.cs` matters (exception handler → Swagger → HTTPS → CORS → authorization → controllers), like the order of Angular interceptors.
- `IDENTITY(1,1)` = auto-increment Id. `SET IDENTITY_INSERT dbo.X ON` lets a script insert fixed Ids (used by the seed so UI routes keep working).
- `FOREIGN KEY` = a column that must point to an existing row in another table (`Books.AuthorId` -> `Authors.Id`); `ON DELETE CASCADE` deletes child rows with the parent. `CHECK` = a rule the database enforces on every write (`Stock >= 0`).
- `GO` separates batches in SSMS scripts; it is not SQL itself. `IF NOT EXISTS ... INSERT` makes a seed re-runnable.
- `CREATE OR ALTER PROCEDURE` = a function that lives in the database; calling it from Dapper is like calling an API endpoint instead of building the query in the client. Re-running the script just replaces it.
- `TOP (@Count)` + `ORDER BY` = `.slice(0, n)` after sorting; `CASE WHEN ... THEN 0 ELSE 1 END` inside `ORDER BY` puts the matching rows first.
- `STRING_SPLIT(@Text, N',')` turns comma text into rows; `OPENJSON(@Json)` turns a JSON array into rows (like `JSON.parse` + iterate), `[key]` is the array index.
- `BEGIN TRANSACTION ... COMMIT` + `SET XACT_ABORT ON` = all statements succeed or none do (any error rolls everything back).
- `using (SqlConnection connection = new ...) { }` = the connection is closed automatically when the block ends, like `finalize()` / unsubscribing in Angular. `DynamicParameters` = the `@Name` arguments sent to the procedure; `CommandDefinition` = procedure name + arguments + cancellation token in one object; `QueryAsync<T>` = run it and map every row to a `T` (column name = property name).
- `Dictionary<int, BookOutputModel>` = TypeScript `Record<number, Book>` / `Map`; used to put each spec on its book without nested searching.
- `AddScoped<BooksRepository>()` = `providers: [BooksRepository]` for one HTTP request; the controller constructor asks for it and ASP.NET injects it (like `inject()`).
- Middleware class = a function in the request pipeline (`InvokeAsync(HttpContext)` calls `await _next(context)` to continue), like an Angular `HttpInterceptor` but for incoming requests; `try/catch` around `_next` catches errors from everything registered after it. `ILogger<T>` = `console.error` with levels, written to the console/Output window; `IHostEnvironment.IsDevelopment()` = `isDevMode()`. Registered with `app.UseMiddleware<T>()`.
- `USE MorisakiBookshop;` = choose which database the script runs in (like `cd`); without it SSMS uses the database selected in the toolbar (often `master`).
- `QueryMultipleAsync` = one stored procedure call that returns several result sets (several `SELECT`s); `reader.ReadAsync<T>()` reads them in order, like destructuring `[total, items]` from a `Promise.all`. `DECLARE @T TABLE (...)` = a temporary in-memory table that lives only during the procedure; `IDENTITY` on it numbers rows in the `ORDER BY` order, used as the row number for paging.
- JWT = a signed text token the server gives after login; the UI sends it back as `Authorization: Bearer ...` (like an Angular `HttpInterceptor` adding a header). `[Authorize]` on a controller/action = Angular `canActivate` guard; `[Authorize(Roles = "Admin")]` = guard that also checks the role. `app.UseAuthentication()` reads the token, `UseAuthorization()` enforces `[Authorize]` (order matters).
- Hashing vs encrypting: a hash cannot be turned back into the password; login hashes the typed password with the stored salt and compares. `Rfc2898DeriveBytes.Pbkdf2` = built-in password hashing; salt = random bytes so equal passwords get different hashes.
- Unique index with `WHERE Email IS NOT NULL` = unique, but many rows may have no value (`UX_Users_Email`).
- Soft delete = a `IsActive BIT` column instead of `DELETE`: the row stays (old orders can still point at it) and every read procedure adds `WHERE IsActive = 1`. `DROP PROCEDURE IF EXISTS` removes a procedure re-runnably.
- `IFormFile` = an uploaded file in a controller (like the `File` object from an Angular `<input type="file">`); the UI sends `multipart/form-data` (`FormData` in TypeScript). `file.CopyToAsync(stream)` writes it to disk; never trust `file.FileName` — a random `Guid` name is used instead.
- `app.UseStaticFiles(...)` = serve files from a folder as plain URLs (like Angular `public/`), here the uploads folder at `/uploads`. `AddSingleton<T>()` = ONE instance for the whole app (vs `AddScoped` = one per request), right for a class that only holds a path.
- `@@ROWCOUNT` = how many rows the last statement touched; comparing it with the expected count after an `UPDATE` tells whether every row passed the `WHERE` (all-or-nothing orders). `ROLLBACK TRANSACTION` undoes everything since `BEGIN TRANSACTION`, `RETURN` leaves the procedure early.
- `JsonSerializer.Serialize(list)` (built into .NET, namespace `System.Text.Json`) = `JSON.stringify`; the property names stay PascalCase, which is what `OPENJSON ... WITH (BookId INT '$.BookId')` in the procedure reads.
- `WHERE Id = @Id AND UserId = @UserId` in every address procedure = server-side ownership check (like an Angular guard, but one the user cannot bypass): the `UserId` comes from the JWT, never from the request body.
- `const string` in a controller = a constant (TypeScript `const`); `private CustomActionResult BuildResult(bool found)` = a small helper method so four actions do not repeat the same 10 lines.
- `MERGE ... USING (...) AS source ON ... WHEN MATCHED THEN UPDATE WHEN NOT MATCHED THEN INSERT` = upsert in one statement: update the row if it exists, insert it if not (like `Object.assign` onto an existing key or a new key). `GROUP BY BookId` + `SUM` first, because MERGE refuses two source rows for one target row. `PRIMARY KEY (UserId, BookId)` = a composite key: one row per user+book pair.
- Account lockout = a counter + a `LockedUntil` time on the user row. Doing `SET Count = Count + 1` in ONE `UPDATE` (not read-then-write in C#) keeps the count right when two requests arrive at the same moment; `SYSUTCDATETIME()` keeps one clock (the database's).
